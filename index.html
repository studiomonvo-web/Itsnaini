    How a live programme is run

    A cohort is a set of dependencies: a client’s participant list, a facilitator’s calendar, a run of live sessions, and records that have to be right at the end. This is how I handle each stage.

    Before the first session

    Settle the dependencies before the first invitation goes out. Participant lists, session dates, facilitator availability and time zones are confirmed with the client in one place, so a change to one does not quietly break another. Joining instructions go out early and access is tested, so day one is spent on the programme and not on logistics.

    During the session

    Run the room so the facilitator can teach. I admit participants, start the recording and keep watch on the room, the chat and the clock. Late joiners and access problems are handled without stopping the session, and the session stays within its time.

    After the session

    Close it out while it is fresh. Recordings and materials reach the participants, attendance and session details are recorded, anything unresolved goes back to the client or facilitator, and the delivery record is updated, so the next session or the next batch starts from accurate information.

    Scheduling across time zones

    Live sessions run on the participants’ clock, and the offsets that cause missed sessions are the ones that change. My local time stays on UTC+7 all year. London moves in March and October, New York in March and November, so the gap is not constant. Pick a city to see where its 09:00 to 17:00 falls on my clock today.
